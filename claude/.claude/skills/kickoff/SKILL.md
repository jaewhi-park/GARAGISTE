Start a new project. Initial requirements: $ARGUMENTS

0. If CLAUDE.md has no "## Language" section, first ask the CEO the working language with AskUserQuestion (options: ko / en / other; default: the language of the CEO's message), run `node .claude/scripts/set-language.mjs --file CLAUDE.md <code>`, and continue in that language. Skip when it is already set.
1. Load the `charter` skill and ask the CEO its question list with AskUserQuestion (split into several calls if the tool limits questions per call). Hand the answers to team-planner to write docs/CHARTER.md.
2. Ask team-planner for 2–3 stack/architecture alternatives with a recommendation, written directly as docs/adr/0001-stack.md with `Status: proposed`. Have team-critic review that file (on REVISE, findings verbatim to the planner, max 2 rounds, per the critic loop), then ask the CEO to confirm. The decision is recorded in step 4 — no separate call.
3. Have team-implementer create the project skeleton per the confirmed docs/adr/0001-stack.md (minimal structure where build, tests and lint pass empty; tell it CLAUDE.md has no Commands section yet, so it runs the stack's standard build/test/lint commands instead) and report the exact commands it ran with their exit codes, and commit the skeleton as `chore(scaffold): <stack> skeleton` (reproduction command in the body). Do not call team-verifier yet — CLAUDE.md has no "## Commands" section for it to run.
4. One team-planner call: (a) write CLAUDE.md per the `claude-md` skill — "## Commands" lists only the commands the implementer reported passing, split quick/full (the one bootstrap case where Commands precede verifier confirmation); (b) set docs/adr/0001-stack.md to `Status: accepted` with the CEO's choice; (c) write a first docs/BACKLOG.md (5–10 items from the charter) and docs/plans/0001-walking-skeleton.md. Then have team-verifier run full verification — PASS confirms both the skeleton and the Commands section. On FAIL, team-implementer fixes (max 3 rounds); a command that still fails after the rounds is dropped from CLAUDE.md by one more team-planner call before step 5, and the CEO is told.
5. Have team-critic review the walking-skeleton plan only if it has 3+ logic steps or is risk:high (the usual threshold; critic loop), then request approval.
6. Have team-implementer commit the files this command wrote, by path — docs/CHARTER.md, docs/adr/0001-stack.md, docs/BACKLOG.md, docs/plans/0001-walking-skeleton.md, CLAUDE.md, docs/README.md, docs/DECISIONS.md if written, .gitignore whenever it is untracked or its `docs/STATUS.md` line is uncommitted (add the line when the installer did not), and .claude/ if not yet tracked — on main, as `docs(kickoff): charter, stack ADR, backlog, plan 0001`. Then run `hire` via the Skill tool (the budget questions go to the CEO; applied and committed after approval) — the project's character is now known. Write docs/STATUS.md (Now: none · Next actions: 1. `/run docs/plans/0001-walking-skeleton.md` in a new session). End by suggesting, in one sentence, a new session and that `/run` there (model assignments load at session start) — no /handoff needed. Do not start it yourself.
