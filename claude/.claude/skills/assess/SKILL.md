Assess an existing codebase and set a rebuild/modernization strategy. Target and context: $ARGUMENTS

0. If CLAUDE.md has no "## Language" section, first ask the CEO the working language with AskUserQuestion (options: ko / en / other; default: the language of the CEO's message), run `node .claude/scripts/set-language.mjs --file CLAUDE.md <code>`, and continue in that language. Skip when it is already set.
1. Load the `legacy-assessment` skill. Send the Explore subagent out per area in parallel to gather the inventory, and have team-planner compile docs/ASSESSMENT.md — pass the Explore reports to it verbatim, do not re-summarize.
2. Report unknowns in chat, then get the preserve/fix policy in one AskUserQuestion call (split only if the tool limits questions per call): the question names each "looks like a bug" item with the planner's default (preserve, per the `parity-harness` skill) and offers "accept all defaults" first and "decide per item" second (then one question per item in follow-up calls); items the planner flagged as charter-conflicting get their own question. The answers go to team-planner verbatim in step 3 and are logged in docs/DECISIONS.md there.
3. Have team-planner compare strategies (strangler fig / module-by-module replacement / full rewrite) with a recommendation and the first seam to replace, written directly as docs/adr/0001-rebuild-strategy.md with `Status: proposed`, and in the same call draft docs/CHARTER.md from the assessment (charter skill template, under 60 lines: Problem and Users from ASSESSMENT.md; Success metrics = parity PASS for every rebuilt seam plus anything the argument named; Non-goals = the rejected strategies and the seams out of scope; Constraints = the preserve/fix decisions; other sections `undecided — at the first /retro`); have team-critic review the ADR (on REVISE, findings verbatim to the planner, max 2 rounds, per the critic loop), then ask the CEO in one AskUserQuestion call to confirm the strategy and the charter's goal, non-goals and success metric (edits go to the planner verbatim). Then one team-planner call sets the ADR to `Status: accepted` with the CEO's choice, applies the charter edits, and writes docs/REBUILD_PLAN.md (step 0 of every rebuild step: extend the parity harness to that step's seam) and CLAUDE.md per the `claude-md` skill ("## Commands" = the build/test commands the inventory found, each flagged `unverified`).
4. Have team-verifier run the Commands section. Then one team-planner call (pass the verifier's per-command results verbatim) removes the `unverified` marker from what passed and drops what failed (a command the guardrail blocked stays marked — tell the CEO its tool must be added to the verifier allow-list by a human), and writes docs/plans/0001-parity-harness-<seam>.md — the harness for the first seam per the `parity-harness` skill, whose last step registers the runner under Commands (do not invoke `/plan`). Have team-critic review that plan past the usual threshold (3+ logic steps or risk:high; on REVISE, findings verbatim to the planner, max 2 rounds, per the critic loop), then request approval with a summary (goal, step count, risks, expected diff) — /run takes only approved plans.
5. Have team-implementer commit the files this command wrote, by path — docs/ASSESSMENT.md, docs/CHARTER.md, docs/adr/0001-rebuild-strategy.md, docs/REBUILD_PLAN.md, docs/plans/0001-parity-harness-<seam>.md, docs/DECISIONS.md, CLAUDE.md, docs/README.md, .gitignore whenever it is untracked or its `docs/STATUS.md` line is uncommitted (add the line when the installer did not), and .claude/ if not yet tracked — on main (if the legacy checkout is on another branch, ask the CEO first), as `docs(assess): assessment, charter, rebuild ADR, rebuild plan, plan 0001`; the legacy tree's other uncommitted changes stay untouched. Run `hire` via the Skill tool (applied and committed after approval) — a rebuild weights critic and reviewer heavily, so assign in that direction. Write docs/STATUS.md (Now: none · Next actions: 1. `/run docs/plans/0001-parity-harness-<seam>.md` in a new session). End by suggesting, in one sentence, a new session and that `/run` there (model assignments load at session start) — no /handoff needed. No rebuild step starts before that plan ships with the harness PASS against legacy.
