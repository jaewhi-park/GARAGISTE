Start a new project from the approved product brief. Note: $ARGUMENTS

The brief's approval was the CEO's "go": from here the team decides and logs; the CEO answers one question (the stack — the most expensive decision to reverse — and the budget) and anything on the escalation list, nothing else. Every step is re-entrant: an output that already exists (the file, the commit) is skipped.

0. Precondition: docs/BRIEF.md with `Status: approved` or `revised` and `Kind: 신규` (from the injected board's Brief line, else grep those two lines — the one file read allowed here). If there is none, or it is still whiteboard or draft, say so in one sentence — "run `/brainstorm <idea, or the path of a document you wrote>` first" — and stop; with `Kind: 레거시`, say so and suggest `/assess <path>` instead. If AGENTS.md has no "## Language" section (a brief committed from elsewhere), ask the CEO the working language with the question tool (options: ko / en / other; default: the language of the brief), run `node .opencode/scripts/set-language.mjs <code>`, and continue in that language.
1. One team-planner call: (a) derive docs/CHARTER.md from docs/BRIEF.md per the `charter` skill (under 60 lines, `Source: docs/BRIEF.md`; a slot the brief leaves undecided gets the planner's default with the reason and a docs/DECISIONS.md line — never a guess presented as fact); (b) write docs/adr/0001-stack.md with 2–3 stack/architecture alternatives and a recommendation, `Status: proposed`, its Context taken from the brief's constraints and risks. Have team-critic review the ADR (on REVISE, findings verbatim to the planner, max 2 rounds, per the critic loop). Then the one question-tool call of this command: the stack (the planner's recommendation first, with its reason), the budget tier (unlimited = API/in-house / high = Max 20x / medium = Max 5x / low = Pro), and any brief Undecided item that meets the escalation criteria (paid services, security or user data, a non-goal conflict) with the planner's default — every other Undecided item is the planner's default, logged. The answers go to the planner verbatim in step 3 and to `hire` in step 5.
2. Have team-implementer create the project skeleton per the chosen docs/adr/0001-stack.md (minimal structure where build and lint pass and one smoke test passes — the test runner wired in and one test that asserts something about the skeleton, so the harness exists; an empty suite is not one; tell it AGENTS.md has no Commands section yet, so it runs the stack's standard build/test/lint commands instead) and report the exact commands it ran with their exit codes, and commit the skeleton as `chore(scaffold): <stack> skeleton` (reproduction command in the body). Do not call team-verifier yet — AGENTS.md has no "## Commands" section for it to run.
3. One team-planner call: (a) write AGENTS.md per the `agents-md` skill — "## Commands" lists only the commands the implementer reported passing, split quick/full (the one bootstrap case where Commands precede verifier confirmation), a "build/run" line so the product can be started from the board, and "## Risk paths" seeded from the stack ADR — the migration, schema, auth, public-API, dependency-manifest and CI/deploy paths this stack has; (b) set docs/adr/0001-stack.md to `Status: accepted` with the CEO's choice and record the step-1 answers and every default in docs/DECISIONS.md (and the brief's Undecided list); (c) write docs/SPEC.md per the `spec` skill — one section per Decided line of the brief, the appendix sketches verbatim under their sections, defaults for the rest — and report the spec report line; (d) write docs/BACKLOG.md — one item per spec section (`spec: F<n>`, completion criteria = the section's Done-when), Later lines as P2, Non-goals under "Excluded"; when /brainstorm already seeded docs/BACKLOG.md from a requirement list, keep those items and add only what is missing — and docs/plans/0001-walking-skeleton.md: the thinnest end-to-end slice of the brief's core flow (its demo scene) through the F-sections it touches, no styling. Then have team-verifier run full verification — PASS confirms both the skeleton and the Commands section. On FAIL, team-implementer fixes (max 3 rounds); a command that still fails after the rounds is dropped from AGENTS.md by one more team-planner call before step 4, and the CEO is told.
4. Have team-critic review docs/SPEC.md as a whole per its spec checklist and, in the same call, the walking-skeleton plan (the first plan is always reviewed). Findings go to the planner verbatim (max 2 rounds, per the critic loop); a finding only the CEO can settle — an escalation item — goes to the CEO at once with the question tool, default attached. The critic's APPROVE on the plan is its approval; at the cap with findings still open, one question-tool call — approve as is / stop here.
5. Commit the files this command wrote yourself, by path — docs/CHARTER.md, docs/adr/0001-stack.md, docs/SPEC.md, docs/BACKLOG.md, docs/plans/0001-walking-skeleton.md, docs/DECISIONS.md, docs/BRIEF.md if changed, AGENTS.md, docs/README.md, docs/STATUS.md, .gitignore if untracked, and .opencode/ and opencode.json if not yet tracked — on main, as `docs(kickoff): charter, stack ADR, spec, backlog, plan 0001`. Write docs/STATUS.md (Now: none · Next actions: 1. `/hire` in this session 2. `/run docs/plans/0001-walking-skeleton.md` in a new session) and commit it by path (`docs(status): kickoff done`). End with one report — the spec sections (F1–F<n>, one line each), what was decided by default (a pointer to docs/DECISIONS.md), and a sentence suggesting `/hire` with the budget tier from step 1 (it applies without a second question and shows the roster) and then a new session with `/run` there (model assignments load at session start) — no /handoff needed. Do not start it yourself.
