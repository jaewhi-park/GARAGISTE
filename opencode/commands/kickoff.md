Start a new project from the approved product brief. Note: $ARGUMENTS

0. Precondition: docs/BRIEF.md with `Status: approved` or `revised` and `Kind: 신규` (from the injected board's Brief line, else grep those two lines — the one file read allowed here). If there is none, or it is still whiteboard or draft, say so in one sentence — "run `/brainstorm <idea, or the path of a document you wrote>` first" — and stop; with `Kind: 레거시`, say so and suggest `/assess <path>` instead. If AGENTS.md has no "## Language" section (a brief committed from elsewhere), ask the CEO the working language with the question tool (options: ko / en / other; default: the language of the brief), run `node .opencode/scripts/set-language.mjs <code>`, and continue in that language.
1. One team-planner call: (a) derive docs/CHARTER.md from docs/BRIEF.md per the `charter` skill (under 60 lines, `Source: docs/BRIEF.md`; a slot the brief leaves undecided stays `undecided — <when>`, never guessed); (b) write docs/adr/0001-stack.md with 2–3 stack/architecture alternatives and a recommendation, `Status: proposed`, its Context taken from the brief's constraints and risks. Have team-critic review the ADR (on REVISE, findings verbatim to the planner, max 2 rounds, per the critic loop). Then one question-tool call: confirm the stack, the charter's goal, non-goals and success metric as derived, and each of the brief's Undecided items with the planner's default (edits and decisions go to the planner verbatim in step 3). No charter questions are asked — the brief already answered them.
2. Have team-implementer create the project skeleton per the confirmed docs/adr/0001-stack.md (minimal structure where build, tests and lint pass empty; tell it AGENTS.md has no Commands section yet, so it runs the stack's standard build/test/lint commands instead) and report the exact commands it ran with their exit codes, and commit the skeleton as `chore(scaffold): <stack> skeleton` (reproduction command in the body). Do not call team-verifier yet — AGENTS.md has no "## Commands" section for it to run.
3. One team-planner call: (a) write AGENTS.md per the `agents-md` skill — "## Commands" lists only the commands the implementer reported passing, split quick/full (the one bootstrap case where Commands precede verifier confirmation); (b) set docs/adr/0001-stack.md to `Status: accepted` with the CEO's choice, apply the CEO's charter edits, and record the Undecided decisions in docs/BRIEF.md and docs/DECISIONS.md; (c) write docs/BACKLOG.md from the brief — one item per Decided line (completion criteria in the brief's words), Later lines as P2, Non-goals under "Excluded"; when /brainstorm already seeded docs/BACKLOG.md from a requirement list, keep those items and add only what is missing — and docs/plans/0001-walking-skeleton.md: the thinnest end-to-end slice of the brief's core flow (its demo scene), no styling. Then have team-verifier run full verification — PASS confirms both the skeleton and the Commands section. On FAIL, team-implementer fixes (max 3 rounds); a command that still fails after the rounds is dropped from AGENTS.md by one more team-planner call before step 4, and the CEO is told.
4. Have team-critic review the walking-skeleton plan only if it has 3+ logic steps or is risk:high (the usual threshold; critic loop), then request approval.
5. Have team-implementer commit the files this command wrote, by path — docs/CHARTER.md, docs/adr/0001-stack.md, docs/BACKLOG.md, docs/plans/0001-walking-skeleton.md, docs/BRIEF.md and docs/DECISIONS.md if changed, AGENTS.md, docs/README.md, .gitignore whenever it is untracked or its `docs/STATUS.md` line is uncommitted (add the line when the installer did not), and .opencode/ and opencode.json if not yet tracked — on main, as `docs(kickoff): charter, stack ADR, backlog, plan 0001`. Write docs/STATUS.md (Now: none · Next actions: 1. `/hire` in this session 2. `/run docs/plans/0001-walking-skeleton.md` in a new session). End by suggesting `/hire` to the CEO in a sentence — the project's character is in the brief, so assign models per role there — and then a new session with that `/run` (model assignments load at session start) — no /handoff needed. Do not start it yourself.
